## ADDED Requirements

### Requirement: Bilingual Docs Routing

The system SHALL serve a documentation section at `/docs/` for English (default locale) and `/vi/docs/` for Vietnamese, with one statically-generated HTML file per documentation slug per locale.

#### Scenario: English docs root loads the introduction page

- **WHEN** a visitor requests `/docs/`
- **THEN** the system returns 200 with the rendered `introduction` page in English
- **AND** the rendered `<html lang>` attribute is `en`
- **AND** the canonical URL header is `https://iamdev.io.vn/docs/`

#### Scenario: Vietnamese docs root loads the introduction page

- **WHEN** a visitor requests `/vi/docs/`
- **THEN** the system returns 200 with the rendered `introduction` page in Vietnamese
- **AND** the rendered `<html lang>` attribute is `vi`
- **AND** the canonical URL header is `https://iamdev.io.vn/vi/docs/`

#### Scenario: Each declared slug emits a static page in both locales

- **WHEN** the site is built with `astro build`
- **THEN** for every key in `DOCS_PAGES`, the build emits `./docs/docs/<slug>/index.html` and `./docs/vi/docs/<slug>/index.html`
- **AND** the build also emits `./docs/docs/index.html` and `./docs/vi/docs/index.html` for the implicit `introduction` slug
- **AND** the build does not emit pages for slugs that are absent from `DOCS_PAGES`

#### Scenario: Unknown slug returns 404

- **WHEN** a visitor requests `/docs/not-a-real-page/`
- **THEN** the system returns Astro's default 404 (no entry was generated by `getStaticPaths`)

### Requirement: Docs Layout Chrome

The system SHALL render every docs page inside a dedicated `DocsLayout` that excludes the marketing `Header` and `Footer` and includes a fixed topbar, a left sidebar, a content column, and a right-hand table of contents.

#### Scenario: Topbar contents

- **WHEN** any docs page renders
- **THEN** the topbar SHALL contain, left-to-right: a brand block (logo + product name + version pill labelled "docs"), a Cmd+K search button (with the keyboard hint), a language segment with VI and EN buttons, a theme toggle button, and an external website link
- **AND** every interactive topbar element SHALL have an `aria-label`

#### Scenario: Sidebar contents

- **WHEN** any docs page renders
- **THEN** the sidebar SHALL render `DOCS_NAV` as four nav groups, each with a group icon, a group title, and the group's slugs as links
- **AND** the link for the current slug SHALL have an `active` visual state

#### Scenario: Marketing chrome is absent

- **WHEN** any docs page renders
- **THEN** the rendered HTML SHALL NOT contain the marketing `<header class="site-header">` element
- **AND** the rendered HTML SHALL NOT contain the marketing footer element

### Requirement: Block-Driven Server Rendering

The system SHALL render docs page content from the typed `Block[]` array stored in `DOCS_PAGES[slug].blocks` server-side, with no inline `<script>` content blob and no client-side hash routing.

#### Scenario: Every block type has a renderer

- **WHEN** a page contains blocks of types `hero`, `h2`, `h3`, `p`, `lede`, `hr`, `ul`, `ol`, `callout`, `code`, `codetabs`, `steps`, `cards`, `features`, or `table`
- **THEN** each block SHALL render to the corresponding HTML structure described in the design document

#### Scenario: First-block hero suppresses auto title

- **WHEN** a page's first block has `t === 'hero'`
- **THEN** the page SHALL NOT prepend an automatic eyebrow + h1 above that block

#### Scenario: Non-hero first block triggers auto title

- **WHEN** a page's first block is anything other than `hero`
- **THEN** the page SHALL render the eyebrow (from `page.eyebrow`) and an `<h1>` (from `page.title`) immediately after the breadcrumb

#### Scenario: Inline markdown shortcuts

- **WHEN** any text passing through the inline-markdown helper contains backtick-wrapped code, `**bold**`, a `[label](href)` link, or a `<kbd>...</kbd>` segment
- **THEN** each shortcut SHALL render to the matching HTML element (`<span class="icode">`, `<strong>`, `<a>`, `<kbd>`)
- **AND** all other special characters in the source SHALL be HTML-escaped before substitution

### Requirement: Cross-Page Slug Links

The system SHALL rewrite inline cross-page links written as `[label](#/<slug>)` inside block content into absolute hrefs of the form returned by `pathFor(lang, '/docs/<slug>/')`, scoped to the current rendering locale.

#### Scenario: Slug rewrite keeps locale

- **WHEN** a block on a `vi` page contains the link `[Cài đặt](#/installation)`
- **THEN** the rendered anchor's `href` SHALL be `pathFor('vi', '/docs/installation/')` (i.e. `/vi/docs/installation/`)

#### Scenario: In-page anchors are preserved

- **WHEN** a block contains a link of the form `[label](#anchor-id)` (no leading slash after the hash)
- **THEN** the rendered anchor's `href` SHALL remain `#anchor-id` and SHALL NOT be rewritten

### Requirement: Heading Identifiers and TOC

The system SHALL emit a stable `id` for every `h2` and `h3` block heading derived from the heading's English text via the existing `headingId(textEn)` helper, and SHALL render a sticky right-hand TOC listing those headings.

#### Scenario: Heading id stability across locales

- **WHEN** a Vietnamese page and its English counterpart contain the same `h2` block
- **THEN** the rendered `id` attribute SHALL be identical in both renders (derived from the EN text)

#### Scenario: Empty TOC hides the column

- **WHEN** a page's blocks contain no `h2` or `h3` blocks
- **THEN** the TOC column SHALL be visually hidden
- **AND** the content column SHALL expand to fill the freed track

#### Scenario: TOC scroll spy

- **WHEN** the user scrolls and a tracked heading enters the viewport's top region (within `topbar-h + 24px`)
- **THEN** that heading's TOC link SHALL receive an `active` visual state
- **AND** the previously active link SHALL lose that state

### Requirement: Page Navigation and Breadcrumb

The system SHALL render a breadcrumb (group title › page title) above the page content and a prev/next pager at the bottom, both driven by `DOCS_NAV` and `DOCS_ORDER`.

#### Scenario: Prev/next derives from flat order

- **WHEN** a page is at index `i` in `DOCS_ORDER`
- **THEN** the prev pager SHALL link to the page at index `i-1` (if any) and the next pager SHALL link to the page at index `i+1` (if any)
- **AND** when no neighbour exists on a side, that side SHALL render an empty placeholder rather than a missing link

#### Scenario: Breadcrumb shows the owning group

- **WHEN** the current slug belongs to nav group `G`
- **THEN** the breadcrumb SHALL show `G.title` followed by a chevron and the current page title

### Requirement: Cmd+K Search Modal

The system SHALL provide a client-side search modal that indexes every page in `DOCS_PAGES` plus every `h2` and `h3` heading, and SHALL be reachable via Cmd+K, Ctrl+K, or `/` (when no input is focused).

#### Scenario: Cmd+K opens the modal

- **WHEN** the user presses Cmd+K (macOS) or Ctrl+K (Windows/Linux) on any docs page
- **THEN** the search modal SHALL open and the input SHALL receive focus within 50ms

#### Scenario: Slash key opens when no input focused

- **WHEN** the active element is not an `<input>` or `<textarea>` and the user presses `/`
- **THEN** the search modal SHALL open

#### Scenario: Empty query lists all pages

- **WHEN** the search input value is empty
- **THEN** the modal SHALL show one result per page (no anchors), in `DOCS_ORDER` sequence

#### Scenario: Query matches title and body

- **WHEN** the user types a query whose lowercased, diacritic-folded form appears in any indexed entry's title or body text
- **THEN** the modal SHALL list at most 12 matching results
- **AND** results that match the title SHALL rank above results that match only the body
- **AND** the matched substring SHALL be wrapped in `<mark>` for visual emphasis

#### Scenario: Keyboard navigation

- **WHEN** the modal is open
- **THEN** ArrowDown / ArrowUp SHALL move the selection (clamped to bounds)
- **AND** Enter SHALL navigate to the selected result's slug (and anchor, if any)
- **AND** Escape SHALL close the modal
- **AND** focus SHALL be trapped inside the modal until it is closed

#### Scenario: No results state

- **WHEN** the user types a query that matches no indexed entry
- **THEN** the modal SHALL display a localized "No results" message (`"Không tìm thấy kết quả nào"` in VI, `"No results found"` in EN)

### Requirement: Code Blocks

The system SHALL render `code` and `codetabs` blocks with a header bar, an optional file name or language label, syntax highlighting for `bash`, `sh`, and `json`, a generic fallback highlighter for other languages, and a copy-to-clipboard button.

#### Scenario: Multi-tab code block switches panes

- **WHEN** the block has `t === 'codetabs'` with multiple tabs
- **THEN** clicking a tab SHALL show that tab's pane and hide the others
- **AND** only the active pane's `<code>` content SHALL be copied when the copy button is pressed

#### Scenario: Single-tab fname header

- **WHEN** the block has `t === 'code'` with a `fname` field
- **THEN** the header bar SHALL show `fname` as the file name label

#### Scenario: Single-tab language fallback

- **WHEN** the block has `t === 'code'` with no `fname` and no `label`
- **THEN** the header bar SHALL show the value of `lang` as the label

#### Scenario: Copy success feedback

- **WHEN** the user clicks the copy button
- **AND** the navigator clipboard API succeeds
- **THEN** the button SHALL switch to a "Copied" / "Đã chép" state for 1600ms before reverting
- **AND** the copy event SHALL be announced via `aria-live="polite"` for assistive tech

#### Scenario: Clipboard fallback

- **WHEN** `navigator.clipboard.writeText` is unavailable or rejects
- **THEN** the component SHALL fall back to a `document.execCommand('copy')` flow on a temporary textarea
- **AND** failures SHALL not surface a visible error (silent fallback)

### Requirement: Theme Persistence

The system SHALL respect the existing site theme system: read/write `localStorage['spec-ade-web:theme']` with values `dark` or `light`, set `document.documentElement.dataset.theme` accordingly, and update the topbar's theme-toggle icon.

#### Scenario: Theme persists across reloads

- **WHEN** the user toggles the theme on a docs page and reloads
- **THEN** the docs page SHALL render with the previously selected theme
- **AND** the same theme SHALL apply on marketing pages (because both share the storage key)

#### Scenario: First-load theme respects OS preference

- **WHEN** no value is stored under `spec-ade-web:theme`
- **THEN** the docs page SHALL render with `dark` theme on systems preferring dark, and `light` on systems preferring light

### Requirement: Language Switch

The system SHALL provide a topbar language segment that, when clicked, navigates to the same slug under the alternate locale.

#### Scenario: Switch from EN to VI keeps slug

- **WHEN** the user is on `/docs/quickstart/` and clicks `VI`
- **THEN** the system SHALL navigate to `/vi/docs/quickstart/`

#### Scenario: Switch from VI to EN at root

- **WHEN** the user is on `/vi/docs/` and clicks `EN`
- **THEN** the system SHALL navigate to `/docs/`

### Requirement: Responsive Behaviour

The system SHALL adapt the docs layout at 1100px and 860px breakpoints.

#### Scenario: Below 1100px hides TOC

- **WHEN** the viewport width is below 1100px
- **THEN** the right-hand TOC column SHALL be hidden
- **AND** the content column SHALL fill the freed track

#### Scenario: Below 860px sidebar becomes a drawer

- **WHEN** the viewport width is below 860px
- **THEN** the sidebar SHALL render as an off-canvas drawer with a scrim
- **AND** a hamburger menu button in the topbar SHALL toggle it
- **AND** the scrim SHALL close the drawer when clicked
- **AND** Escape SHALL close the drawer

### Requirement: Header Discoverability

The system SHALL surface the docs section from the marketing header on every non-docs page.

#### Scenario: Desktop header has a Docs link

- **WHEN** any marketing page renders the desktop header
- **THEN** the primary nav SHALL include a `Docs` (EN) / `Tài liệu` (VI) link between the existing `Features` and `Pricing` entries
- **AND** the link SHALL point to `pathFor(lang, '/docs/')`

#### Scenario: Mobile nav has a Docs link

- **WHEN** any marketing page renders the mobile nav
- **THEN** the same Docs link SHALL appear, in the same position relative to Features and Pricing

### Requirement: Content Coverage

The system's `DOCS_PAGES` SHALL contain entries for exactly the following 13 slugs, each present in `DOCS_NAV` exactly once.

| Group | Slugs |
| --- | --- |
| Get started | `introduction`, `quickstart`, `installation` |
| Core concepts | `projects-sessions`, `panes-tabs`, `chat`, `terminal`, `file-editor` |
| Features | `git`, `database`, `send-with-goal`, `spec`, `monitor` |
| Reference | `settings`, `shortcuts` |

#### Scenario: All slugs in NAV exist in PAGES

- **WHEN** the build runs
- **THEN** every slug listed in any `DOCS_NAV[i].items` array SHALL be a key in `DOCS_PAGES`
- **AND** no `DOCS_PAGES` key SHALL be absent from `DOCS_NAV`

#### Scenario: Each page has minimum content shape

- **WHEN** any page in `DOCS_PAGES` is read
- **THEN** it SHALL have a non-empty bilingual `title` and `eyebrow`
- **AND** its `blocks[0]` SHALL be of type `hero` or `lede`
- **AND** it SHALL contain at least two `h2` blocks

#### Scenario: New pages port user-guide content

- **WHEN** the new pages `file-editor`, `monitor`, `settings`, and `spec` are read
- **THEN** their content SHALL faithfully convey the corresponding chapters in `user-guide/05-file-editor.md`, `user-guide/09-monitor.md`, `user-guide/10-settings.md`, and `user-guide/12-spec.md` respectively, with bilingual translations (VI source, EN translation)

#### Scenario: Renames are reflected

- **WHEN** the build runs
- **THEN** the legacy slug `chat-terminal` SHALL be absent from `DOCS_PAGES`
- **AND** the legacy slug `goal` SHALL be absent from `DOCS_PAGES`
- **AND** the new slugs `chat`, `terminal`, and `send-with-goal` SHALL be present

### Requirement: Accessibility

The system SHALL meet WCAG 2.1 AA-relevant baseline behaviours throughout the docs section.

#### Scenario: Skip link

- **WHEN** the user presses Tab from a fresh page load
- **THEN** the first focusable element SHALL be a skip-to-content link that, when activated, focuses the main content region

#### Scenario: Focus trap on overlays

- **WHEN** the search modal or the mobile sidebar drawer is open
- **THEN** Tab and Shift+Tab SHALL cycle focus only within that overlay
- **AND** Escape SHALL close the overlay and return focus to the element that opened it

#### Scenario: Single h1 per page

- **WHEN** any docs page renders
- **THEN** it SHALL contain exactly one `<h1>` element

#### Scenario: Color contrast

- **WHEN** any docs page renders in either `dark` or `light` theme
- **THEN** body text and link colors against their backgrounds SHALL meet WCAG 2.1 AA contrast minimums (≥ 4.5:1 for body text, ≥ 3:1 for large text and UI components), inherited from the existing tokens in `src/styles/global.css`

### Requirement: Test Coverage

The system SHALL include a Playwright test file `tests/docs.spec.ts` that exercises the docs section.

#### Scenario: Smoke

- **WHEN** the test runs against the dev server
- **THEN** `/docs/` and `/vi/docs/` SHALL each return 200 and render a visible `<h1>` or hero heading

#### Scenario: Sidebar navigation

- **WHEN** the user clicks a non-current sidebar link on `/docs/`
- **THEN** the URL SHALL change to that slug
- **AND** that link SHALL gain the `active` state

#### Scenario: Language switch on a deep slug

- **WHEN** the user is on `/docs/quickstart/` and clicks `VI` in the topbar
- **THEN** the URL SHALL become `/vi/docs/quickstart/`

#### Scenario: Theme toggle persists

- **WHEN** the user toggles the theme on `/docs/` and reloads the page
- **THEN** `document.documentElement.dataset.theme` SHALL match the toggled value

#### Scenario: Search opens and navigates

- **WHEN** the user presses Cmd+K (or Ctrl+K) on `/docs/`, types a substring of an existing page title (e.g. `git`), selects the first result, and presses Enter
- **THEN** the URL SHALL change to that page's slug

#### Scenario: TOC anchor jump

- **WHEN** the user clicks any TOC item on `/docs/`
- **THEN** the page SHALL scroll such that the corresponding heading is in view (within `topbar-h + 24px` of the viewport top)

#### Scenario: Mobile drawer

- **WHEN** the viewport is 375px wide and the user clicks the topbar menu button
- **THEN** the sidebar drawer SHALL become visible
- **AND** clicking the scrim or pressing Escape SHALL close it
